# 用真人面试校准报告

报告现在的验证都是模型扮演的候选人：评分稳不稳、作弊迹象报不报得出来，是在模拟面试上量的。真人说话有口头禅、会紧张、会被打断，作弊的方式也不按剧本来，这些只有真人面试才能量。这份说明讲怎么组织一轮真人面试、让评审独立打分、再把评审的结论和报告对起来。

工具都在这个 crate 里，不调用模型，不联网，不花钱：

- `examples/calibrate.rs`：生成评分表、生成记录实际情况的文件、对照统计。
- `calibration/form.html`：评审填的评分表，一个不联网的网页。
- `src/calibration.rs`：评分表和统计结果的数据结构，`calibrate()` 是对照的入口。

这一步对应 issue #46，放在下一轮迭代的开头做。

## 要回答的问题

1. 报告的建议（强烈建议进入、建议进入、待定、不建议）和有经验的面试官看完录像给的结论，一致到什么程度。
2. 每道题和每项能力的评分，和人打的分差多少，是普遍偏高还是偏低。
3. 安排了作弊的面试，报告报出来多少，种类说得对不对，指的题对不对。
4. 没作弊的面试，报告冤枉了多少。网络差、设备坏、有人进屋这些情况会不会被当成作弊。
5. 简历里夸大的经历，报告认出来多少；实话又被怀疑了多少。
6. 报告引用的证据（哪一分哪一秒说了什么）对不对得上录像。
7. 评审觉得报告有没有用，看一场录像要多久。

## 找多少人，面多少场

统计出来的是比例，场数少的时候比例晃得很厉害。工具给每个比例都算了 95% 的置信区间，下面是几个例子：

| 结果 | 区间 |
| --- | --- |
| 8 场作弊报出 8 场 | 68% 到 100% |
| 8 场作弊报出 7 场 | 53% 到 98% |
| 10 场正常面试没有误报 | 误报率 0% 到 28% |
| 20 场正常面试没有误报 | 误报率 0% 到 16% |
| 20 对结论里 18 对一致 | 70% 到 97% |
| 30 对结论里 27 对一致 | 74% 到 97% |

所以：

- **至少 24 场，最好 30 场以上。** 评审的结论和报告的对比不到 20 对时，工具会提示样本太少，结果只能当个例看。
- **评审 2 到 3 位**，要有实际面试经验。每场面试至少一位评审，其中至少 10 场要有两位评审各自独立打分。两位评审之间的一致程度是报告能达到的上限：人和人都只有七成一致的话，不能要求报告和人九成一致。
- **扮演候选人的 6 到 10 位**，每人面 3 到 4 场，换不同的岗位和情况。同一个人演太多场，结果反映的是这个人，不是报告。

## 演哪些情况

24 场的一种排法（场数多就按比例加）：

| 情况 | 场数 | 记录实际情况时的 `kind` |
| --- | --- | --- |
| 正常作答，水平高低都要有（强、一般、弱大致各三分之一） | 8 | 不填 |
| 照着答案念：事先写好的稿子，或者现场用另一台设备让 AI 生成再念 | 2 | `read_answers` |
| 旁边有人出声提示 | 2 | `prompted` |
| 低头看手机查答案 | 2 | `phone_lookup` |
| 切到别的窗口查答案，或者往页面里粘贴 | 2 | `left_page` |
| 简历里写了没做过的项目，或者把参与写成主导，面试时照着简历说 | 4 | `resume_inflated` |
| 网络差：中途断网、限速 | 2 | `network_trouble` |
| 设备出问题：话筒或摄像头中途失灵、换设备 | 1 | `device_trouble` |
| 和面试无关的打扰：来电话、有人进屋说话、有人从身后走过 | 1 | `interruption` |

几点说明：

- 作弊的场次不要每道题都作弊。挑两三道题做，并且记下是哪几道，这样才能量报告指的题对不对。
- 作弊要演得像真的想不被发现，不要故意演得很明显。
- 「对着 AI 说话想影响评分」（`manipulation`）在模拟面试里已经量过，想再量可以加一两场。
- 替考（`impersonation`）不用演。报告不做人脸比对（属于生物识别，见 README 的「关于录像和声音的分析」），演了只会得到一个已知的结果。
- 简历夸大的场次，扮演的人要事先写好哪几段是编的。这类场次只算进简历核验，不算进作弊的漏报和误报。
- 正常作答的人要用自己真实的经历，或者一份自己很熟的经历，否则会被当成简历夸大。

## 开始之前

- **知情同意。** 扮演的人和评审都要知道：面试会录像录音，录像和转写会发给大模型分析，材料只用于这次校准。同意的记录留在组织的人手里，不进仓库。
- **数据只留在运行环境里。** 录像、转写、简历、报告、评分表都是个人信息，不进 Git，不贴进 issue、PR 和聊天。仓库是公开的。要记录结果时只写统计数字和脱敏后的现象。
- **评审用代号。** 评分表里只有代号（比如 `hr-1`），代号对应谁由组织的人自己记。
- **定好用哪个版本。** 校准期间不要改提示词。报告里有 `prompt_version` 和 `model`，对照的时候所有报告应该是同一个版本。
- **用正式的方式部署。** 真语音识别、真语音合成、真模型（`scripts/serve.sh`，见 `docs/deploy.md`）。用假的语音识别量出来的结果没有意义。

## 步骤

下面的命令都在仓库根目录跑。目录名是例子，放在仓库外面。

### 1. 面试

在后台建岗位、候选人和面试，把链接发给扮演的人。组织的人给每一场记一句安排了什么（下一步要填进文件）。逐题问答和实时对话两种方式都要有。

### 2. 导出报告

面试结束、报告生成好以后，把每场的报告存成一个 JSON 文件。登录后台之后在同一个浏览器里打开 `{后台地址}/api/v1/interviews/{面试 id}/report`，把内容存下来；或者用 curl 带上登录的 cookie 取。接口返回的整个对象可以直接用，不用把 `content` 拆出来。

```text
~/calibration/reports/<面试 id>.json
```

### 3. 记下每一场的实际情况

```bash
cargo run -p interview-report --example calibrate -- truth ~/calibration/reports/*.json --out ~/calibration/sessions.json
```

生成的文件里每场面试一条，`behaviours` 是空的。正常作答的不用动，别的照安排填：

```json
{
  "interview_id": "…",
  "behaviours": [
    { "kind": "prompted", "question_ids": ["q2", "q3"], "note": "家人在旁边小声说了两次" }
  ],
  "note": ""
}
```

`question_ids` 是报告里题目的 `question_id`，说不清在哪几道题上就留空。一场面试可以有几条。之后再跑这个命令只会补上新的面试，已经填的不会被覆盖。

### 4. 给评审生成评分表

```bash
cargo run -p interview-report --example calibrate -- form ~/calibration/reports/*.json \
  --annotator hr-1 --annotator hr-2 --out ~/calibration/forms
```

每场面试、每位评审一个 HTML 文件。评分表里只有题目和六项能力的名称，没有报告的任何结论。

### 5. 评审独立打分

把这些给评审：评分表、录像文件、岗位说明、候选人的简历。录像在后台的面试详情页可以下载，由组织的人下载好再给。**不要让评审自己打开后台的面试详情页，那一页上有报告。**

评审用浏览器打开评分表，看完录像，填第一步：

- 每道题一个分：5 优秀、4 良好、3 合格、2 较弱、1 不合格，可以给半分。和报告用的是同一把尺子。
- 六项能力各一个分（1 到 5 的整数），看不出来的可以不填。
- 简历可信度、有没有觉得候选人在作弊（觉得有的话写在哪里）、结论和理由、看这一场花了多少分钟。
- 勾上「在看 AI 的报告之前填的」，点「保存评分表」，会下载一个 JSON 文件。

没勾这一项的评分表不算进一致程度的统计。

### 6. 评审对着报告核对

第一步的文件交上来以后，再把报告给评审看（后台的面试详情页）。评审打开同一个评分表，点「接着填」载入刚才保存的文件，填第二步：

- 抽查报告里的证据（建议每场十条）：点开时间点，看录像里是不是这么说的。记抽查了几条、对不上的几条。
- 报告哪里说错了、漏了什么，一行一条。
- 报告有没有用（1 到 5），看完报告会不会改自己的结论。

第一步填的内容不要再改。保存，把文件交回来。同一位评审同一场面试交了两个文件的话，对照时用保存得晚的那个（文件里记了保存的时间），所以第二步的文件要包含第一步的内容（「接着填」载入以后就是这样）。浏览器给第二个文件起的名字可能带「(1)」，不用改。

收回来的文件都放进一个目录：

```text
~/calibration/annotations/<面试 id>.<评审代号>.json
```

### 7. 对照

```bash
cargo run -p interview-report --example calibrate -- stats \
  --reports ~/calibration/reports --annotations ~/calibration/annotations \
  --truth ~/calibration/sessions.json --out ~/calibration/result.json
```

结果打印在终端里，`--out` 另存一份 JSON。存下来的结果里只有数字、面试 id 和评审的代号，没有录像和转写的内容，但「要逐个看的不一致」里有报告的一句结论，贴到公开的地方之前自己看一眼。

## 结果怎么读

每个比例后面都带区间，比如 `7/8（88%，区间 53% 到 98%）`：8 场里 7 场，真实的比例有 95% 的把握落在 53% 到 98% 之间。**先看区间，再看比例。**

| 段落 | 说的是什么 |
| --- | --- |
| 建议和评审的结论 | 「完全一样」和「一样或只差一档」。「报告偏宽、偏严」是报告比评审高了还是低了。下面的表是每种组合有几对 |
| 评分 | 平均差多少分；报告平均比人高还是低（偏差）；差在半分、一分以内的占多少；相关系数（人觉得好的题，报告是不是也觉得好） |
| 评审之间 | 两位评审看同一场，彼此一致到什么程度。这是上限。下面每位评审一行，看有没有哪一位特别严或者特别宽 |
| 诚信迹象 | 「报了」指报告的诚信风险是中或高。安排了作弊报出多少（剩下的是漏报）、种类对不对、证据是不是落在安排的那几道题上；正常作答和只有干扰的场次被报了多少（误报） |
| 简历核验 | 「起了疑心」指简历可信度是低，或者有简历存疑的复核提示 |
| 评审对着报告核对 | 证据对得上多少、报告说错和漏掉几处、有用程度、会不会改结论、看一场多少分钟 |
| 要逐个看的不一致 | 按严重程度排：漏报、误报、结论差两档以上、简历没认出、简历被冤枉、结论差一档、单题差 1.5 分以上。每一条都要回到录像和报告里看是谁的问题 |

读的时候留意：

- 报告和评审不一致，不一定是报告错。先看两位评审之间一不一致，再逐条看。
- 偏差比平均差更值得看。报告普遍高半分可以整体调，忽高忽低才是问题。
- 漏报和误报要分开种类看。照着念和看手机只凭文字、计时和几秒一帧的画面推断，本来就比切出页面难（README 的「哪些可靠，哪些只能参考」里写了各自的可靠程度）。

## 及格线（提议，下一轮开头和 Ryan 定）

量出来之前没法知道哪条线合理，下面是提议。达不到的先逐条看不一致，再决定是调提示词还是改报告里的说法。

| 指标 | 提议的线 |
| --- | --- |
| 结论一样或只差一档 | 90% 以上，并且没有差两档以上的 |
| 结论完全一样 | 不低于两位评审之间的一致程度减 10 个百分点 |
| 逐题评分的平均差 | 0.75 分以内，并且不超过两位评审之间平均差的 1.5 倍 |
| 逐题评分的偏差 | 正负 0.3 分以内 |
| 逐题评分的相关系数 | 0.6 以上 |
| 切出页面、旁人提示这两种作弊 | 都报出来 |
| 照着念、看手机 | 报出一半以上。达不到就在报告里把这两类的可靠程度写得更低 |
| 正常作答被报成中或高风险 | 一场都不能有 |
| 只有网络、设备、打扰的被报成中或高风险 | 一场都不能有 |
| 简历夸大认出来 | 七成以上 |
| 实话被怀疑 | 一成以内 |
| 抽查的证据对得上 | 95% 以上 |

## 量完以后

- 评分整体偏高或偏低：改评分标准的提示词，`PROMPT_VERSION` 加一，重新生成样例，跑 `lab evaluate` 和 `stability`（见 README 的「试验台」）。
- 某一类作弊漏得多：先看是没有信号（转写里看不出来、画面没拍到），还是有信号但模型没用上。没有信号的，改报告和 README 里对可靠程度的说法；有信号的，改提示词。
- 误报：每一条都要找到原因。宁可漏，不冤枉人。
- 改完以后用同一批面试重新生成报告（后台的「重新生成」，或者接口 `POST /api/v1/interviews/{id}/report/regenerate`），评分表不用重填，再跑一遍 `stats` 看有没有变好。注意这时候是在同一批数据上调，变好的幅度会偏乐观，最好留三分之一的场次只在最后看一次。
- 把结果写进 README 的「实测结果」：只写统计数字和脱敏后的现象。

## 用模拟面试走过一遍流程

2026-11-16 用 22 场模拟面试（候选人由模型按人设扮演，逐题问答、实时对话、带语音识别错字的都有）把上面的步骤走了一遍，为的是确认工具能用，**不能当成校准的结果**：

- 评分表在真的浏览器里填过：第一步保存，换一个浏览器「接着填」，第二步保存；手机宽度下能填；没填代号、载入别的面试的文件会被拦住。
- 实际情况按场景的人设填（场景里写了安排的是什么），这一部分的数字是真的：安排了作弊的 7 场都报了，种类都对得上，写明了题目的 5 场证据都落在对应的题上；正常作答的 9 场和只有干扰的 3 场没有误报；简历夸大的 8 场认出 7 场，漏的一场简历可信度是「中」；简历是实话的 14 场没有被怀疑。
- 评审那一部分是为了试工具随手填的 6 份评分表，数字没有意义，这里不写。

模拟的候选人作弊是按剧本来的，比真人容易认，所以上面的漏报率和误报率只是下限的参考，真人面试的结果以校准为准。
