# 候选人面试页：真机验证

云端的浏览器测试只有 Chromium 加假的摄像头和麦克风。候选人多半在手机上从微信里点开链接，下面这些只能拿真手机确认：权限弹窗、录出来的文件能不能播、声音会不会自动播、来电话和锁屏之后能不能接着面试、发热和流量。

这份文档给两种人用：前半部分给拿着手机试的人，照着一步一步做、在表里打勾就行，不用懂技术；后半部分给开发者，讲怎么准备和出了问题怎么查。对应的 issue 是 #15。

## 要试哪些环境

| 编号 | 环境 | 说明 |
| --- | --- | --- |
| A | iPhone，Safari | 最要紧的一个：iPhone 上所有浏览器用的都是 Safari 的内核 |
| B | iPhone，微信里点开链接 | 候选人最常见的打开方式 |
| C | 安卓手机，微信里点开链接 | 同上 |
| D | 安卓手机，Chrome 或系统自带浏览器 | |
| E | Mac，Safari | |
| F | 电脑，Chrome 或 Edge | 对照用，云端测的就是这个内核，应该全部通过 |

有条件的话再加：企业微信、钉钉、飞书里点开链接（页面会提醒换到系统浏览器，看提醒有没有出现）。

每个环境要一条**自己的**面试链接，一条链接只能面试一次。开发者会提前造好，按编号发给你。

## 开始之前

- 找一个安静的地方，手机电量在 50% 以上，连 Wi-Fi。
- 记下手机型号、系统版本、微信或浏览器的版本（微信在「我 → 设置 → 关于微信」里看）。
- 另外准备一部手机，中间有一步要给正在面试的手机打电话。
- 面试里随便回答就行，说什么不重要，每题说十几秒。

## 照着做

每一步后面写着「应该看到什么」。和写的一样就在结果表里打 ✓，不一样打 ✗ 并写下看到了什么，能截屏就截一张。某一步在这个环境里做不了（比如电脑没有来电话）写「不适用」。

### 一、打开链接到开始面试

1. 点开链接。
   应该看到：欢迎页，有岗位名称和「开始准备」按钮。在微信里打开时，页面上方多一条「你正在微信里打开」的提醒，带一个「复制链接」按钮。
2. 点「开始准备」，把同意事项全部勾上，点其中一项右边的箭头。
   应该看到：箭头点开有详细说明；没勾全时「同意并继续」点不了，勾全了能点。
3. 点「同意并继续」，再点「允许使用摄像头和麦克风」。系统弹窗问是否允许时，**先点「不允许」**。
   应该看到：页面出现红色的说明，告诉你去哪里把权限改回来。
4. 按页面上的说明把摄像头和麦克风改成允许，回到页面点「重新检测」。
   应该看到：摄像头一栏出现你自己的画面（像照镜子一样左右相反），麦克风一栏在你说话时音量条会动，并显示「听到你的声音了」。
5. 点「播放提示音」。
   应该看到（听到）：「叮」的一声。听到后点「听到了」。
6. 看网络一栏。
   应该看到：「上传速度够用」，或者提醒网速偏慢（提醒了也能继续）。
7. 点「下一步」，再点「开始面试」。
   应该看到：面试官开始说话，**不用再点任何东西就有声音**；页面上方有「录制中」和计时。

### 二、正常答题

8. 听完第一个问题，直接开口回答十几秒，然后停下来不说话。
   应该看到：回答的时候「我答完了，下一题」按钮就在屏幕上，不用往下滑；停下来以后出现一个倒计时的圆圈，走完自动进入下一题。页面上的字没有被屏幕边切掉的。
9. 第二题回答几秒后，点「我答完了，下一题」。
   应该看到：马上进入下一题，不用等倒计时。
10. 下一题播完以后点「再听一遍题目」。
    应该看到：题目重新播一遍。
11. 回答时中间停两三秒想一想，在倒计时走完之前接着说。
    应该看到：倒计时消失，没有被跳到下一题。

### 三、中途被打断

下面每一步做完都接着答题，确认面试还能往下走。

12. 面试官说话或者你回答的时候，切到别的应用（比如回到桌面），等 5 秒再切回来。
    应该看到：面试还在，能接着进行。如果出现「声音被暂停了」，点「继续面试」之后能接着进行。
13. 按电源键锁屏，等 10 秒再解锁回到页面。
    应该看到：同上。
14. 用另一部手机给这部手机打电话，响几声后挂掉（先试不接，有余力再试一次接起来说两句再挂）。
    应该看到：出现「声音被暂停了」或者「摄像头或麦克风断开了」，计时停住；电话结束后点「继续面试」或「重新连接」，面试接着进行。
15. 戴着有线或蓝牙耳机的话，中途把耳机拔掉或关掉。
    应该看到：可能出现「摄像头或麦克风断开了」，点「重新连接」之后接着进行；或者什么提示都没有、声音改从手机喇叭出来，也算正常。
16. 打开飞行模式，等 20 秒再关掉。
    应该看到：出现「网络不稳定」的提醒，面试没有中断；网络回来以后提醒消失。
17. 刷新页面（微信里是右上角菜单里的「刷新」）。
    应该看到：回到欢迎页，按钮是「检查设备，继续面试」；重新检查设备以后，从刚才那一题接着问，不是从头开始。
17b. （手边有第二台设备时做，比如手机加电脑）面试进行中，在另一台设备上打开同一条链接，检查设备以后点「继续面试」。
    应该看到：另一台设备从刚才那一题接着问；原来这台几秒之内停下来，显示「面试已经在另一个页面里继续了」，过一会儿出现「回到这个页面继续面试」的按钮。之后留在哪一台上把面试做完都可以，后面的步骤在那一台上做。
18. 把手机放在桌上不碰，等 2 分钟（让面试官问、你答，只是手不碰屏幕）。
    应该看到：屏幕一直亮着，没有自己熄灭。

### 四、结束

19. 答完所有问题，或者点右上角的「结束」再点「结束面试」。
    应该看到：先是「面试结束了，正在保存录像」和进度条，然后变成「面试完成，谢谢你」或「面试已结束」。从结束到保存完大概等了多久，记在表里。
20. 把页面关掉，再点一次同一条链接。
    应该看到：还是结束页，不会重新开始面试。

### 五、实时对话（开发者会另外给一条标着「实时对话」的链接）

只在 A、C 两个环境各试一次就够。**不戴耳机，用手机喇叭外放。**

21. 正常回答几个来回。
    应该看到：你说完以后面试官一两秒内接话；面试官说话时不会被自己的声音打断，或者偶尔停一下马上接着说。
22. 面试官说到一半时直接开口说话。
    应该看到：面试官停下来听你说，接下来回应的是你刚说的话。
23. 面试官说话时咳嗽一声。
    应该看到：面试官停一下就接着说。

### 六、英文面试（开发者会另外给一条标着「英文」的链接）

只在一个环境试一次就够。

24. 从头走到尾。
    应该看到：页面上所有的字都是英文，包括同意事项和结束页。看到中文的地方截屏记下来。

### 七、长时间（只在一部 iPhone 和一部安卓上各做一次）

25. 用一条 30 分钟的面试链接完整走一遍，开始前和结束后各记一次电量；在系统设置里看这段时间浏览器或微信用了多少流量；结束时摸一下手机背面烫不烫。

## 给开发者：怎么准备

- 照 `docs/deploy.md` 用 `scripts/serve.sh` 起一套正式的（真的语音合成和语音识别）。不要用 `scripts/dev.sh`：它的面试官声音是提示音，「声音会不会自动播」「面试官的声音在不在录像里」试不出真实情况。
- 摄像头和麦克风只在 https 下能用，所以要一个手机能访问的 https 地址，写进 `AI_INTERVIEW_PUBLIC_URL`，做法见 `docs/deploy.md` 的「让候选人能打开面试链接」。用临时隧道的话，试完之前不要重启隧道，地址变了发出去的链接就打不开了。
- 在 HR 后台造面试，候选人信息用编的（不要填试的人的真实姓名和手机号）：
  - 每个环境一场逐题问答，3 到 4 道题，静音时长用默认值。
  - 实时对话两场（A、C 各一场），英文一场，30 分钟的两场。
  - 链接按环境编号发给试的人。链接就是凭证，不要发到群里。
- 试完以后在 HR 后台逐场看：
  - 录像能不能播、能不能拖动进度、有没有画面和声音、声音和画面对不对得上、面试官的声音在不在录像里。
  - 被打断过的那几场，录像分成了几段、每一段是不是完整（刷新一次应该多一段）。
  - 每个回答有没有转写出文字。
  - 报告里的过程事件对不对得上试的人做过的事（切后台、断网）。

## 给开发者：出了问题怎么查

每场面试的过程事件在 `GET /api/v1/interviews/{id}/events`（要 HR 登录），在跑服务的那台机器上也可以用 `DATABASE_URL=<服务用的数据库> cargo run -p interview-room --example demo -- state <面试的 ID>` 看（还带对话记录和录像的情况）。和真机有关的几种：

| 事件 | 看什么 |
| --- | --- |
| `page_opened` | `in_app_browser`（认出来是哪个应用的内置浏览器）、`recording_mime`（录像选了哪种容器和编码；安卓和电脑上的 Chrome 是 webm，iPhone 上多半是 mp4，是空的说明浏览器一种都不认）、`signals`（这个浏览器里哪些过程事件采得到） |
| `device_check`、`device_report` | 设备检测卡在哪一步、失败的原因、测出来的上行网速 |
| `screen_wake_lock` | `supported`、`held`：屏幕常亮申请到了没有 |
| `recording_gap`、`device_recovered` | `device` 是 `camera`、`microphone` 还是 `audio_output`（声音被系统停掉），`cause` 是原因，`duration_ms` 是停了多久 |
| `recording_error` | 录制器报的错误名；带 `kept_in_memory: true` 的是本机存不下录像、分片改放内存接着传（录像应该还是完整的） |
| `upload_stalled`、`upload_recovered`、`upload_finished` | 录像传不动的原因、攒了多少片、结束后等了多久才传完 |
| `visibility_hidden`、`visibility_visible` | 切后台、锁屏的时间点 |
| `page_taken_over` | 这条链接在另一个页面（另一台设备、另一个标签页）里点了「继续面试」，这个页面停了下来。候选人没有这么做却出现了这一条，说明链接被别人打开了 |

常见问题对应去哪里看代码：

- 权限、设备检测：`web/apps/candidate/src/lib/media/capture.ts`、`errors.ts`。
- 录像的容器和编码：`src/lib/recording/mime.ts`；后端合并分片在 `crates/interview-room/src/recording.rs`。后端收到分段 MP4（Safari 和 iPhone 录的那种）以后合并成能拖动的文件、面试中边传边转写，云端有测试（`crates/interview-room/tests/recording.rs` 和 `transcribe.rs` 里带 mp4 的两条），用的是 ffmpeg 造的 MP4；真手机录出来的要是合并失败或者没有转写，先拿那场的分片对比这两条测试里的文件差在哪。
- 声音不自动播、被系统停掉：`src/lib/media/audio-graph.ts`、`output-watch.ts`。
- 内置浏览器的识别和提醒：`src/lib/flow/capabilities.ts`。
- 屏幕常亮：`src/lib/media/wake-lock.ts`。

每个确认的问题开一个 issue（标 `line:room`，挂在 #15 下面），写上环境、步骤和面试 ID，不写试的人的个人信息。
